# 배분 규칙 보강

> 사용법: 한 번 손으로 해 본 작업의 순서를 아래 4칸에 채워 저장합니다.
> 저장 위치: `.agents/skills/<스킬 이름>/SKILL.md` (이 양식 폴더는 그대로 두고 복사해서 씀)
> 다음부터는 "○○ 스킬대로 해 줘" 한 줄로 같은 순서를 반복합니다.
>
> 상태: 검증 완료(2026-11-10, S4 ②). 근거: 처리지침.md(확정본) 제3장 · 별표 1(조직도) · 별표 2(배분기준표)
> 첫 적용에서 반영한 6개(원본과 다른 행 6개): R001 「예산」 제외어 `추진 실적` · R056 「언론」 제외어 `부처 입장` · 새 규칙 R305 홍보담당관 「언론 관련」(1) · R136 「민원 서비스」 우선순위 1→3 · R211 「안전등급」 1→3 · R181 「지방채」 1→2
> 결과: 시험 1순위 29 → 39/40 · 3순위 안 40 → 40 · 접수대장 1순위 440 → 495 · 새로 틀린 문항 시험 0 · 접수대장 0 · 남은 오답 T25

## 1. 언제 쓰는지
- 배분 엔진(web/engine.js)의 1순위 정확도를 올려야 할 때, 또는 틀린 배분이 새로 보고되어 규칙을 고쳐야 할 때
- 입력: `node test_engine.js [규칙.csv]`가 내는 틀린 문항 표, `data/배분기준표_소관키워드_304건.csv`(원본, 읽기만), `data/A부_조직도_26개과.csv`
- 출력: `data/rules_보강.csv`(사본), 전후 비교표, PROGRESS.md 기록

## 2. 순서
1. **틀린 문항을 원인별로 묶는다.** `node test_engine.js data/rules_보강.csv`(사본이 없으면 인자 없이)를 실행하고, 틀린 문항을 「정답 과를 이긴 규칙(근거키워드)」과 「문장 형태」로 묶어 표로 만든다. 같은 키워드가 여러 과에 걸린 경우와, 짧은 키워드가 다른 과의 긴 키워드 안에 들어 있는 경우(예: 「예산」 ⊂ 「교육 예산」)도 따로 센다.
2. **원인마다 고칠 방법을 1개씩 제안한다.** 새 규칙의 과는 조직도 26개 과 안에서만 고른다. 제안마다 시험 40건·접수대장 520건 결과를 **파일을 바꾸지 않고** 메모리에서 미리 재어 함께 보여 준다.
   - 제외어 추가: 일반어 규칙이 이긴 경우, 그 문장 형태에만 나오는 말을 제외어로 붙인다(예: 「예산」에 `추진 실적`).
   - 키워드 추가: 제외어 때문에 후보가 없어지는 문항이 생기면, 그 문항만 잡는 더 구체적인 키워드를 새 규칙으로 넣는다(예: 홍보담당관 `언론 관련`).
   - 우선순위 조정: 정답 과의 구체 키워드가 일반어 규칙보다 점수가 낮을 때 우선순위를 올린다(예: 「민원 서비스」 1→3).
3. **사용자가 고른 방법만 사본에 반영한다.** 사본이 없으면 원본을 복사해 `data/rules_보강.csv`를 만든다(utf-8-sig BOM·CRLF 유지). 바꾼 행의 비고 칸에 「S4② 제외어 추가」·「S4② 우선순위 1→3」처럼 적고, 새 규칙은 마지막 번호 다음(R305…)으로 붙인다. 반영하기 전 사본을 한 벌 떠 두고, 반영 뒤 `diff 원본 사본`으로 다른 행이 고른 것뿐인지 확인한다.
4. **고치기 전·후를 표로 비교한다.** `node compare_rules.js`(인자 없으면 원본 → rules_보강.csv)를 실행해 시험 40건 1순위·3순위 안, 접수대장 520건 1순위, 조직도 밖 규칙, 새로 틀린 문항을 얻는다. 같은 날 여러 번 고쳤으면 `node compare_rules.js 직전사본.csv data/rules_보강.csv`로 이번 변경만의 효과도 본다.
5. **바꾼 규칙과 결과를 PROGRESS.md에 적는다.** rule_id·바꾼 칸·값, 4번 표의 숫자, 남은 오답과 그 이유를 한 행으로 적는다.

## 3. 끝나는 조건
- 시험 40건 1순위가 30건(75%) 이상
- `compare_rules.js` 출력에서 시험·접수대장 모두 「새로 틀린 문항 0건」
- 시험 3순위 안이 고치기 전보다 줄지 않고, 조직도 밖 규칙 0건
- `diff` 결과 원본과 다른 행이 사용자가 고른 규칙뿐이고, PROGRESS.md에 전후 숫자가 기록됨

## 4. 하지 말 것
- 원본 `data/배분기준표_소관키워드_304건.csv`를 고치지 않는다(사본만 고침).
- 사용자가 고르지 않은 방법을 반영하지 않는다.
- 조직도 26개 과 밖의 과를 새 규칙에 넣지 않는다.
- 시험 한 문항만 맞히려는 규칙(예: T25 하나를 위한 제외어 「교육 예산」)을 넣지 않는다. 다른 문항을 틀리게 할 수 있으므로 접수대장 520건에서 새 오답이 0건인지 반드시 확인한다.
- 숨은 시험세트(`05_비교실험_숨은시험세트`)를 열어 규칙을 맞추지 않는다(채점 전용).
- 엔진 코드(web/engine.js)에 규칙을 직접 쓰지 않는다(규칙은 CSV에서만 읽음).
