# 자료요구서 문항 분해

> 상태: **검증 일부 완료**(2026-11-09). [확인] ①②③ 통과, ④ 강사 기준본 비교는 **미완료**.
> 기준본을 받아 비교한 뒤 차이가 있으면 이 파일을 고치고 이 줄을 지운다.
> 근거: 처리지침_초안.md 제9조(문항 분해) · 제27조(개인정보) · 지침재료/01 인수인계서 2절

## 1. 언제 쓰는지
- 국회 의원실에서 자료요구서 PDF를 받아 문항 목록을 만들어야 할 때
- 입력: `원문/*.pdf` (파일명에 문항 수가 있음. 예: `자료요구서_기획재정위원회_의원K_25문항.pdf`)
- 출력: `data/문항목록.csv` (열: 파일명·위원회·의원·제출기한·문항번호·요구내용·세부항목·비고, utf-8-sig)

## 2. 순서
1. `python split.py` 를 이 폴더에서 실행한다(pypdf 필요). 새 요구서는 `원문/`에 넣기만 한다.
2. 줄 판정 규칙(split.py에 들어 있음)
   - 첫 줄 「○○위원회 ○○ 의원실 자료요구서」 → 위원회·의원
   - 「수신: … 제출기한: YYYY. M. D.」 → 제출기한 `YYYY-MM-DD`
   - 「수신:」「담당 보좌관:」「끝.」 줄 → **버린다**(보좌관 이름·연락처 저장 금지)
   - 줄 맨 앞 「숫자.」 → 새 문항(문항번호 = 그 숫자)
   - 「가.」~「하.」 → 앞 문항의 세부항목, 「※」 → 앞 문항의 비고(여러 개면 ` / `로 합침)
   - 그 밖의 줄(줄바꿈으로 잘린 문장) → 바로 앞 항목 뒤에 이어 붙인다
3. 화면에 나오는 파일별 표 「파일명 | 파일명의 문항 수 | 뽑은 문항 수 | 마지막 번호 | 번호 연속 | 일치」를 확인한다. 하나라도 X면 종료 코드 1로 끝난다.
4. [확인] 아래 4가지를 순서대로 본다.
   - ① 파일별 문항 수 = 파일명의 문항 수 = 마지막 번호, 번호 연속
   - ② 원문 대조: 파일마다 문항 1개씩 골라 요구내용·세부항목·비고가 PDF와 같은지 본다. 세부항목·비고 **개수**도 원문에서 센 값과 같아야 한다.
   - ③ 개인정보: CSV에 「홍길동」「02-000」「보좌관」「수신:」이 0건
   - ④ 강사 기준본 비교: 내 파일을 `문항목록_내것.csv`로 이름을 바꾸고, 기준본을 `data/`에 넣은 뒤 「두 파일의 다른 행만 표로 보여 줘」
5. PROGRESS.md에 파일별 문항 수, 합계 행 수, [확인] 결과를 적는다.

## 3. 끝나는 조건
- ① 모든 파일 「일치 O」 (2026-11-09 기준: 의원K 25 · 의원R 34 · 의원C 19 = 78행)
- ② 원문 대조 3건 일치, 세부항목·비고 개수가 원문과 같음 (2026-11-09 기준: 세부 14·36·12, 비고 4·6·7)
- ③ 개인정보 검색 0건
- ④ 기준본과 다른 행 0건, 또는 다른 행마다 이유를 적음 → **미완료**(기준본 아직 없음)

## 4. 하지 말 것
- `원문/` PDF와 `data/`의 기존 파일을 고치지 않는다(결과는 새 파일 `data/문항목록.csv`에만 쓴다).
- 세부항목 정규식에 `[가-하]`를 쓰지 않는다. 「가」~「하」 사이의 **모든 한글 음절**이 걸려 「끝.」 같은 줄도 세부항목이 된다. 14자 `[가나다라마바사아자차카타파하]`를 쓴다.
- 보좌관 이름·연락처를 어떤 칸에도 저장하지 않는다.
- 문항 수가 안 맞을 때 CSV를 손으로 고치지 않는다. 원인 줄을 찾아 규칙을 고친 뒤 다시 실행한다.
- 「타 부처 소관」처럼 범위 밖으로 보이는 문항도 분해 단계에서는 빼지 않는다(판정은 S4 배분에서 「확인필요」로).
